# 未下载资源：用途、学习阶段与按需获取方法

核查日期：2026-10-19。按使用者要求，停止困难及大型文件下载，不在本地保留残缺数据包。已清理本次约 176 MiB 下载分片。以下地址均来自官方作业代码、Notebook、课表或论文页面；文件大小来自本次 HTTP 响应，按 MiB（1024² 字节）近似，解压后空间通常更大。**本文命令供未来需要时自行执行，本次未执行这些大文件下载。**

推荐优先在 Colab 临时运行环境获取数据和模型，避免占用本地磁盘。Colab `/content/` 在会话结束后会被清理；确需长期保留的代码、答案和实验结果再保存到 Drive。默认 Notebook 会把不少资源放进 Drive，因此想节省云盘也应明确选择临时路径。

## 1. 哪些学习阶段需要再下载什么

| 学习阶段 | 需要按需获取的资源 | 未下载的影响 | 最省空间的办法 |
|---|---|---|---|
| NumPy/数学、讲义阅读 | 无新增大型资源 | 可以直接开始 | 使用本地笔记、插图、讨论课 |
| A1 kNN/Softmax/全连接 | CIFAR-10，约 162.6 MiB 压缩包 | 仍能写推导与跑小张量检查，不能完整训练/评价 CIFAR | 学到 A1 时只获取一次，在 Colab 用 |
| A2 BN/Dropout/CNN/PyTorch | 同一份 CIFAR-10 | 完整数据实验依赖它 | 复用 A1 数据，不重新存三份 |
| A2 RNN、A3 Transformer captioning | 课程 COCO captioning，约 987.3 MiB | 缺图像特征、caption、词表，不能完成数据部分 | 在 Colab 临时磁盘解压，复用于两次作业 |
| A3 ViT、SimCLR | CIFAR-10；SimCLR 预训练权重约 94.2 MiB | ViT 数据训练、SimCLR 预训练比较尚不能直接运行 | 分阶段获取；先做小张量损失检查 |
| A3 DDPM | Emoji 约 28.6 MiB、检查点约 142.7 MiB；CLIP 模型另下 | 加噪公式可学，完整生成缺数据/权重 | 使用预训练检查点，避免从头长训练 |
| A3 CLIP/DINO | CLIP/DINO 权重、hub 源码；COCO；DAVIS | 零样本、检索和分割需额外获取 | CLIP 与 DINO 依次加载，DAVIS 最后再下 |

| 2025 视频、评分/考试 | 校内权限 | 公开仓库无法提供完整课程平台体验 | 走合法课程账号；用公开往年视频辅助概念 |

学习指南的阶段 0–3 可先开始，不必等待高级模型权重。只想理解原理时，下载大数据并不是前置条件；要声称完成训练和达到题目指标时则必须使用相应数据与评价条件。

## 2. CIFAR-10：最早需要的数据

- 用途：A1 图像分类、A2 网络训练、A3 ViT 和 SimCLR。10 类 32×32 彩图，标准 50000 张训练图、10000 张测试图；作业还会从训练部分划验证集。
- 获取：[数据集说明](https://www.cs.toronto.edu/~kriz/cifar.html)、[Python 版压缩包](https://www.cs.toronto.edu/~kriz/cifar-10-python.tar.gz)。约 162.6 MiB，解压约需更多同量级空间。
- 本地存放：`datasets/cifar-10-python.tar.gz`；准备脚本解压到 `datasets/cifar-10-batches-py/`，在各作业的 `cs231n/datasets/` 创建相对链接。

未来下载示例，从仓库根执行：

```bash
curl -L --fail --retry 3 -C - https://www.cs.toronto.edu/~kriz/cifar-10-python.tar.gz -o datasets/cifar-10-python.tar.gz
python tools/prepare_datasets.py
```

不要在归档未下载完整时运行解压脚本。A3 的 torchvision 用 `CIFAR10(root='data', download=True)`，可以让它管理自己的缓存；若要复用归档，需遵守 torchvision 对 `root` 下的文件布局和完整性检查。不要假设 NumPy 目录的相对链接会自动覆盖 torchvision 缓存。

## 3. 课程版 COCO captioning：最大的一项，建议云端用

- 用途：A2 RNN captioning、A3 Transformer captioning，以及 CLIP 题中的部分输入。包含课程准备的图像特征、caption、词表等，并非完整 COCO 数据集。
- 地址：[课程版 COCO](https://cs231n.stanford.edu/coco_captioning.zip)，约 987.3 MiB 压缩，解压另占空间；它是本次停止下载的主要对象。
- 本地路径：`datasets/coco_captioning.zip` → 解压为 `datasets/coco_captioning/`，用准备脚本链接到 A2/A3。

```bash
curl -L --fail --retry 3 -C - https://cs231n.stanford.edu/coco_captioning.zip -o datasets/coco_captioning.zip
python tools/prepare_datasets.py
```

在 Colab 的省空间做法：在 `/content/` 下载、解压，把作业 `cs231n/datasets/coco_captioning` 链接到临时目录，或在调用 `load_coco_data(base_dir=...)` 时明确提供实际路径。以当前作业的 `coco_utils.py` 接口为准。作业中的原始 `get_coco_dataset.sh` 在其当前目录下载/解压，因此要先切换到正确目录；A3 注释里的 `get_coco_captioning.sh` 文件并不存在，实际脚本名为 `get_coco_dataset.sh`。

`load_coco_data(max_train=...)` 只缩减载入训练样本，不会把服务器归档下载大小缩小。不必为本题额外下载整个 COCO 2014/2017 图像集。

## 4. SimCLR 预训练权重

- 用途：A3 `Self_Supervised_Learning.ipynb` 用预训练 encoder 初始化，再进行短训练与下游分类对照。可避免从头进行原 Notebook 所述长时间预训练。
- 地址：[2025 官方存储](https://cs231n.stanford.edu/2025/storage/a3/pretrained_simclr_model.pth)，约 94.2 MiB；Notebook 原首选地址为 `http://downloads.cs.stanford.edu/downloads/cs231n/pretrained_simclr_model.pth`。
- 路径：`assignments/assignment3/assignment3/pretrained_model/pretrained_simclr_model.pth`。

在 A3 根目录：

```bash
mkdir -p pretrained_model
curl -L --fail --retry 3 -C - https://cs231n.stanford.edu/2025/storage/a3/pretrained_simclr_model.pth -o pretrained_model/pretrained_simclr_model.pth
```

按 Notebook 读取 `model.load_state_dict(torch.load(...), strict=False)`。`trained_simclr_model.pth` 是你继续训练产生的结果，未提供不属于仓库缺项。可以先完成 augmentation 和 contrastive loss 小测试，学到预训练比较时再下载。

## 6. CLIP、DINO 与 DAVIS：由库管理的下载

### CLIP ViT-B/32

用途：A3 零样本分类、图文检索、DDPM 文本条件编码。入口为 [OpenAI CLIP 官方仓库](https://github.com/openai/CLIP)。在相应环境安装 Notebook 指定的库后：

```python
import clip
model, preprocess = clip.load('ViT-B/32', device='cuda', download_root='/content/clip-cache')
```

没有 GPU 时将 device 改成 `'cpu'`；模型仍需空间和内存。CLIP ViT-B/32 权重通常为数百 MB，以运行时实际版本为准；官方库源码中的 `_MODELS` 维护精确下载 URL 和校验信息，本次未下载且未独立测量大小。`download_root` 可以指定临时目录，默认通常是 `~/.cache/clip/`。

本次未把整个 CLIP 项目或权重存进课程仓库；已经下载的是 CLIP 原理图，而不是可执行模型。

### DINO ViT-S/8

用途：A3 attention map、patch feature PCA、视频分割。入口：[facebookresearch/dino](https://github.com/facebookresearch/dino)。Notebook 原调用：

```python
import torch
torch.hub.set_dir('/content/torch-hub')  # 可选，指定临时缓存
dino_model = torch.hub.load('facebookresearch/dino:main', 'dino_vits8')
```

该调用会获取 hub 代码和官方权重；ViT-S/8 约 2200 万参数，检查点通常为几十到约百 MB，精确大小由上游文件决定，本次未下载。默认常见缓存为 `~/.cache/torch/hub/`，权重还可能位于其 `checkpoints/`。离线使用需要同时准备模型定义和兼容权重，单独另存论文 PDF 没有帮助。

### DAVIS 视频分割数据

用途：`CLIP_DINO.ipynb` 的最后一部分，使用单帧标注训练轻量 patch 分类器，再评价同视频其他帧。入口：[DAVIS 项目](https://davischallenge.org/)、[TensorFlow Datasets DAVIS](https://www.tensorflow.org/datasets/catalog/davis)。

本仓库 `DavisDataset` 直接调用 `tfds.load('davis/480p', split='validation', as_supervised=False)`。数据准备过程可能涉及完整源归档与 TFDS 转换缓存，即使选择 validation 也不代表只下载一个视频。可能占 GB 量级，本次未测量也未下载。

省本地空间时在 Colab 使用 `TFDS_DATA_DIR` 环境变量指定 `/content/tfds`，并在导入/创建数据集之前设置；也可在自己的代码副本中给 `tfds.load` 传 `data_dir`。原题指定的 sample 和帧索引用于对照评价，随意替换视频后不应再声称与原题指标等价。

## 9. 存储管理和未来下载脚本

`resources/download_manifest.json` 中 `ok` 表示实际存在并校验过；`deferred` 表示遵照本次要求暂不下载，原失败原因仍作为历史信息保留。未完成片段已清理，未来按需下载不会接着使用残缺分片。

`tools/download_materials.py` 默认跳过 `deferred`；只有主动传入 `--retry-deferred` 才重试，`--only` 可只选一个文件。例如想补 SimCLR 论文：

```bash
python tools/download_materials.py --retry-deferred --only 2020_SimCLR.pdf
```

想补 emoji：

```bash
python tools/download_materials.py --data --retry-deferred --only emoji_data.npz
```

脚本保留单文件 256 MiB 上限，COCO 应使用本文手动命令或 Colab，不会默认批量下它。下载以后执行 `python tools/prepare_datasets.py` 可布置共享数据链接，`python tools/audit_repository.py` 可更新审计结果。归档完整且解压核验后，你可以自行决定是否保留压缩包；共享数据的符号链接避免重复复制，但上传 Drive 或跨平台复制时要确认工具会如何处理链接。
